📘 Custom Template Guide

Learn how to create interactive templates for fxAI using the universal fxai.js library and fxai.css stylesheet.

1. What Is a Template?

A template is an HTML file that defines the UI and logic for a specific interactive experience – e.g., a quiz, flashcard deck, adventure, or language exercise. When you import a template, you provide three pieces of metadata:

  • Name – a unique identifier (e.g., "Language Quiz").
  • Description – a short, clear explanation of what the template does.
  • JSON Schema – the exact data structure the AI must generate.

2. The Description’s Dual Role

The description serves two critical purposes during the initial request:

  1. Template Selection – it helps the AI understand the purpose of each template so it can choose the right one based on the user's prompt.
  2. Content Generation – it guides the AI on what kind of content to produce when filling the JSON schema. For example, if the description says "German B1 grammar quiz with translations", the AI will generate German grammar questions with English translations.
📌 Prompt Flow – Initial Request (Selection + Generation):
System prompt includes for each active template:
  • Name: "Language Quiz"
  • Description: "Interactive language quiz with clickable sentence for translation..."
  • Schema: {"topic": "string", "questions": [...]}

AI uses the description to:
  1. Decide which template matches the user's request.
  2. Generate the actual content (topic, questions, translations, etc.) that fits the schema.

Continuation (Regenerate/Extend):
System prompt includes description, schema and current data.

3. Metadata Fields Explained

Template Name

  • Must be unique among active templates.
  • The AI will output this exact name in its response.
  • Case‑insensitive fallback is available, but exact match is recommended.

Template Description

  • A short (1‑2 sentences) description of what the template does.
  • Used by the AI during the initial selection for two purposes:
    • To understand the template's purpose and decide when to select it.
    • To guide the content generation – the AI uses the description to know what topics, difficulty, language, or style to use when filling the schema.
  • Example: "Generate a 5‑question German B1 grammar quiz with translations and grammar explanations."
  • Best practice: Be specific about the content type, topic, difficulty, and any special features – this helps the AI generate relevant, high‑quality data.

JSON Schema

  • A JSON object that defines the structure of the data object the AI must generate.
  • Must match exactly what your template expects in window.templateData.
  • Example: {"topic": "string", "questions": [{"question": "string", "options": ["string"], "correct": 0}]}
  • The AI will always generate data that conforms to this schema – both in initial generation and in continuations. The description influences the actual values placed into these fields.

4. Universal Library (fxai.js)

The shared library handles all the heavy lifting:

  • State extraction – FXAI.init(rawData) separates _state from the data.
  • Persistence – FXAI.persist() saves the current state back to the app.
  • Loading overlay – FXAI.showLoading(msg) and FXAI.hideLoading().
  • AI continuation – FXAI.generateNext(prompt) automatically shows the overlay and calls the bridge.
  • Memory & logging – FXAI.saveProgress(), FXAI.getMemory(), FXAI.log(), FXAI.showToast().
  • Debug panel – FXAI.showDebug() opens a floating panel with logs and a JS executor (see section 8).

Include it in your template with <script src="fxai.js"></script>.

5. Universal CSS (fxai.css)

A shared stylesheet provides a consistent look and common components:

  • Layout: .fxai-container, .fxai-header, .fxai-card
  • Buttons: .fxai-btn, .fxai-btn-primary, .fxai-btn-success, .fxai-btn-danger
  • Inputs: .fxai-input
  • Choices: .fxai-choice
  • Utilities: .fxai-hidden, .fxai-error, .fxai-text-center
  • Loading overlay (used by fxai.js)

Include it with <link rel="stylesheet" href="fxai.css">. You only need to add template‑specific overrides.

6. Required JavaScript Functions

Every template must define these two global functions:

  • window.render() – called when new data is injected. Use FXAI.init() to get clean data and restore state, then update the UI and call FXAI.persist().
  • window.getState() – called by the app to persist runtime state (e.g., current question index, score). Must return a plain object.

7. Data Lifecycle

  • New session – the AI generates a full data object. The app injects it as window.templateData and calls render(). Your template uses FXAI.init() to extract the data and restore any saved state.
  • Continuation – your template calls FXAI.generateNext(userPrompt). The AI returns an updated data object (same schema). The app injects the new data and calls render() again.
  • State persistence – after any UI change, call FXAI.persist() to save the current state. The app will store it in history.

8. Debugging Tools in fxai.js

The library includes a powerful debug panel:

  • FXAI.showDebug() – opens a floating panel with a scrollable log area and a JavaScript executor.
  • FXAI.log(message) – writes a message to the panel, browser console, and Android logcat.
  • FXAI.evalJS(code) – executes a JavaScript expression and logs the result (you can also use the panel's input field).
  • FXAI.debugData(showAlert) – prints the current window.templateData to the panel and console.

To open the debug panel, run FXAI.showDebug() in the browser console (via Chrome DevTools). Use it to inspect the AI's response and test fixes interactively.

9. Example: Language Quiz Template

Here's a complete template with clickable sentence translation overlay, multiple‑choice answers, and grammar explanations.

Metadata:

  • Name: Language Quiz
  • Description: "Generate a 5‑question German B1 grammar quiz. Each question must include a sentence with a blank, four options, the correct answer index, and a grammar explanation."
  • JSON Schema: {"topic": "string", "questions": [{"sentence": "string", "translation": "string", "question": "string", "options": ["string"], "correct_index": 0, "grammar_explanation": "string"}]}
💡 Why this description works:
• "5‑question" – tells the AI how many items to generate.
• "German B1 grammar" – specifies the language and level.
• "sentence with a blank" – describes the question format.
• "translation" – guides the AI to include translations.
• All these details help the AI generate relevant, high‑quality content that matches your template's design.

10. Adding the Template in Settings

  1. Place your HTML file in the internal storage (or assets folder).
  2. Open the app → Settings → Templates → Add Template.
  3. Fill in the Name, Description (be specific – it influences content generation), and JSON Schema (as a single‑line string).
  4. Select your HTML file from storage.
  5. Save – the template is now available for selection (and the AI can choose it and generate content for it).

11. Continuation with FXAI.generateNext()

  • Call FXAI.generateNext(userPrompt) from your template (e.g., on button click).
  • The library shows a loading overlay and sends the prompt to the AI.
  • The AI returns a complete updated data object that matches your schema.
  • The app injects the new data and calls window.render().
  • Your template should replace the old data with the new one (or merge if needed).
  • Preserve client‑side state (e.g., current index, score) in _state and restore it in render().

12. Testing & Debugging Workflow

  • Use FXAI.log(message) – logs to the debug panel, browser console, and Android Logcat.
  • Enable Chrome remote debugging (chrome://inspect) to view the WebView console.
  • Open the debug panel with FXAI.showDebug() to inspect the raw AI response and test JavaScript expressions.
  • If your template fails, an error dialog will appear. Use the debug panel to see the exact error and data.

13. Best Practices

  • Write descriptive, specific descriptions – they guide both template selection and content generation. Include details like topic, difficulty, number of items, and format.
  • Keep schemas simple – avoid unnecessary nesting.
  • Test with the debug panel – verify that the AI's data matches your expectations.
  • Use the universal library – it handles persistence, loading, and debugging for you.
  • Name your template uniquely – avoid collisions with other active templates.
